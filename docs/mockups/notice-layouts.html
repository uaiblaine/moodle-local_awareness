Os sete layouts

Cada cartão diz para que o layout serve, quais níveis de insistência aceita e em que versão entra. A investigação de viabilidade recomenda quatro na v1 (Clássico, Destaque, Tela cheia, Cartão) e adiar os outros três. Clique para levar ao palco.

Carrossel: de onde vêm os slides

A ideia em avaliação: o autor escreve uma lista com marcadores no editor de conteúdo e cada item vira um slide. Uma imagem no item é a foto do slide; um link de vídeo no item (montado pelo filtro multimídia) é o vídeo do slide; o texto do item é a legenda. O que estiver fora da lista fica como texto do aviso.

O que o plugin lê
  1. Slide 1 · foto — a imagem do item; legenda: "Novo laboratório de informática no bloco C, com 40 estações."
  2. Slide 2 · foto — idem.
  3. Slide 3 · vídeo — o player que o filtro multimídia montou para o link; legenda: "Tour de 90 segundos pelo aplicativo Moodle."
  4. Texto do aviso — os dois parágrafos fora da lista, exibidos abaixo da legenda.

Funciona tecnicamente: o plugin lê a lista depois que o corpo entra no modal (é aí que as URLs de arquivo e os players já existem) e classifica cada item pelo invólucro .mediaplugin. O que a investigação apontou contra: não há esquema para o autor, nada valida ao salvar, e toda lista já escrita vira slides no instante em que o aviso muda para Carrossel. Um item com duas imagens ou uma lista aninhada falha na frente do leitor, não no editor.

Como fica no formulário

A seção Aparência do modal ganha três campos antes de Largura e Altura. Nada é movido por JavaScript: o layout é um grupo de radio com rótulos em HTML (o template de elemento do core renderiza rótulos sem escapar), a posição é outro grupo de radio, a animação é um select. Tela cheia oculta o campo Posição (hideIf); as demais combinações inválidas são recusadas na validação do servidor, com o motivo.

Decisões embutidas na proposta

Cada uma está aberta a revisão; o texto diz o que foi assumido e o que a investigação no código confirmou.

Avisos existentes não mudam nada

Padrão de banco classic / center / none: o upgrade é um no-op visual. Só o formulário de aviso novo sugere Esmaecer, e um teste garante que editar um aviso antigo não o migra para Esmaecer sem querer.

Um template Mustache, layouts por classe

O core cria o modal a partir de um único TEMPLATE por classe JS e o plugin reutiliza a instância na fila. Classes próprias (la-tpl-*, la-pos-*, la-anim-*), nunca utilitários do Bootstrap 5: no 4.5 eles não existem para este diálogo.

Fila: esconder, trocar, mostrar

show() do core não faz nada num modal já visível, então a entrada é disparada pelo plugin em cada aviso. Se a forma muda entre dois avisos, o diálogo é escondido antes de trocar as classes; se não muda, só o conteúdo troca.

Todo layout continua um modal de verdade

Fundo escurecido, foco preso, aria-modal. Isso já é assim hoje em todos os níveis de insistência. Faixa e Cartão são modais pequenos ancorados à borda, não toasts; a ajuda do campo diz isso ao autor.

O scrim é um só, irmão do diálogo

O fundo escurecido é um singleton do core preso ao body; nenhuma classe no diálogo o alcança. Scrim mais leve para o Cartão exige alternar uma classe no próprio backdrop pelo JS. Fica como decisão explícita, não como efeito do CSS.

Deslizar deriva da posição

Uma opção em vez de quatro: a direção é a borda mais próxima (centro desliza do topo). Menos vocabulário para o autor, mesma expressividade.

Imagem muda de papel por layout

Clássico e Minimalista mantêm a imagem de fundo de hoje. Destaque e Cartão a usam como faixa, Dividido como painel lateral. Faixa e Tela cheia a ignoram. O campo passa a chamar-se "Imagem", com ajuda por layout; corte/foco fica adiado de forma declarada.

Movimento reduzido vence o autor

prefers-reduced-motion e body.behat-site colapsam toda entrada para esmaecer e desligam o "tremor" de clique recusado, que hoje não tem guarda. Um teste varre o CSS e exige as duas guardas em cada animação.

Cabeçalho nunca sai do DOM

O × e o nome acessível do diálogo (aria-labelledby) moram no cabeçalho. Minimalista e Faixa removem o cromo (fundo, borda, espaçamento), nunca o elemento.

A pré-visualização vira uma ida ao servidor

O Preview de hoje entrega ao core/modal_cancel o HTML cru do editor. Com vídeo e slides isso engana: o filtro multimídia roda em PHP. Um web service de prévia devolve conteúdo, vídeo e slides já renderizados, e o diálogo real (ModalNotice) os mostra com botões que não registram nada.

Painéis sobre imagem leem o tema

Os painéis translúcidos de hoje são brancos fixos e ficam ilegíveis no tema escuro do 5.x. Entram nos tokens --bs-*/--* junto com o layout Destaque, e o bloco de tokens --la-* passa a ser declarado também em .awareness, senão nada dentro do diálogo os enxerga.

Vídeo: o player é do site, e já há JS na página

O servidor embrulha a URL num link e o filter_mediaplugin monta o player. O suposto bloqueio (o JS do video.js não viaja no web service) foi refutado por medição: o media_videojs/loader já está em toda página nas três versões e setBody() dispara o evento que o inicializa.

Vídeo para quando o aviso some

hide() do core só troca classes: o áudio continuaria tocando de um diálogo invisível. O plugin sobrescreve hide() para pausar mídia, descartar players e limpar iframes; entre dois avisos da fila o setBody() já cuida disso. Sem autoplay em nenhum caso.

Slides estruturados, não a lista

Ler <ul><li> funciona, mas sem esquema, sem validação ao salvar e reinterpretando toda lista já escrita. A recomendação é uma tabela de slides com grupo repetido no formulário (precedente: qtype_ddimageortext); o híbrido (ler a lista ao salvar e gravar na tabela) fica como opção.

Carrossel próprio, sem o do Bootstrap

As classes de transição do carrossel do Bootstrap são aplicadas pelo JS dele e mudam de nome entre 4.5 e 5.2; object-fit-cover, ratio-* e d-grid não existem no 4.5. AMD próprio (~120 linhas, sem jQuery), classes próprias, padrão WAI-ARIA de carrossel, sem rotação automática.

viável com mudanças  Rodada 1 (layouts, posição, animação; 29 agentes) e rodada 2 (vídeo e carrossel; 17 agentes) sobre o plugin e o core 4.5/5.1/5.2: funciona nas três versões, com a mecânica ajustada como descrito acima. O relatório completo está em docs/MODAL-LAYOUTS-FEASIBILITY.md.
